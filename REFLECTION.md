# Reflection — Credex AI Audit

## 1. The Hardest Bug
The most frustrating bug I encountered was a hydration mismatch on the Results page specifically when navigating via shareable URLs. Because I was using `useSearchParams` to fetch the audit ID, and then fetching that audit data within a `useEffect`, the initial server-render had no data, while the client-render eventually did. This caused the typical "Text content does not match" error, but it also broke the Framer Motion animations because the DOM elements were being ripped out and replaced during the hydration phase.

To debug this, I first hypothesized that it was a simple race condition. I tried wrapping the entire component in a `Suspense` boundary, but the error persisted. I then realized that Next.js 14 handles `useSearchParams` differently in production builds, sometimes forcing the entire page into client-side rendering if not wrapped correctly. I tried using a loading state, but that caused the "flash" of unstyled content. 

The breakthrough came when I realized I was trying to render the "Audit Summary" (generated by AI) which contained random whitespace characters from the Groq API. The server was rendering a "skeleton" without these characters, and the client was injecting them too early. I solved it by creating a `NoSSR` wrapper for the dynamic parts of the report and ensuring that all data fetching was strictly client-side for shared audits, while using a proper `Suspense` boundary with a dedicated `loading.tsx` to handle the initial mount. This stabilized the DOM and allowed the animations to trigger reliably.

## 2. Mid-Week Course Correction
Mid-week, I initially planned to use an LLM (GPT-4) to perform the entire audit logic. I thought it would be "smarter" and able to handle nuanced edge cases better than hardcoded rules. I spent half of Day 2 building a prompt that fed the tool list into the LLM and asked for savings. 

However, I reversed this decision within 4 hours. I realized that for a financial tool, "hallucinations" are fatal. The LLM would occasionally suggest downgrading a plan to one that didn't exist, or it would miscalculate the total savings by a few dollars. In finance, if the math is wrong once, the user loses trust in the entire product. I decided to pivot back to a **Deterministic Audit Engine** written in TypeScript. By coding the rules manually (e.g., "If seats < 3 and tool is Claude Team, recommend Pro"), the tool became 100% predictable, testable, and auditable. I kept the AI only for the "Summary" section—the "flavor text" that explains the *why* behind the numbers—where its creative strength is an asset, not a liability. This hybrid approach (Deterministic Math + AI Insights) proved much more robust.

## 3. Week 2 Strategy
If I had a second week, I would focus on **Direct API Integrations**. Currently, the tool relies on manual input (the user selects their tools). In Week 2, I would implement "One-Click Audit" via OAuth for GitHub, OpenAI, and Anthropic. By pulling the actual usage logs and seat counts directly from their APIs, we could find even deeper savings—like identifying specific users who have seats but haven't logged in for 30 days.

Secondly, I would build the **"Transition Workflow"**. Finding savings is step one; actually switching is step two. I’d add a feature that generates the exact email templates or provides a "switch" button that uses browser automation (or direct API calls) to actually downgrade the plans or cancel redundant subscriptions. This moves the tool from "Information" to "Execution," which is where the real value lies for busy founders. Finally, I’d build a "Company-wide Dashboard" for CFOs to track these optimizations over time across different departments.

## 4. AI Tool Usage
I used **Antigravity (Gemini 1.5 Pro)** as my primary pair programmer. It was invaluable for scaffolding the Tailwind CSS layouts and generating the complex Mermaid diagrams for `ARCHITECTURE.md`. I also used it to write the boilerplate for the 16 unit tests, which saved hours of repetitive work. 

However, I did not trust the AI with the **deterministic financial logic**. When I asked it to write the `runAudit` function initially, it missed several edge cases regarding seat minimums (e.g., forgetting that ChatGPT Team requires at least 2 seats). I had to manually audit its code and rewrite the logic to ensure it was legally and financially accurate. 

A specific instance where the AI was wrong: I asked it to generate the `PRICING_DATA.md` sources. It "hallucinated" that Windsurf Pro was $10/month. I caught this because I had the official pricing page open and knew it was $15. This reinforced my decision to always use AI for *structure* and *explanation*, but never for *ground-truth data* without a manual verification step.
